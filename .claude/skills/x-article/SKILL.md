# X記事(キジ)作成 — スクール講師グルコンのノウハウ

X記事は短文ポストとは全く別のノウハウ体系(引用戦略・マネタイズ・タイトル設計・セールスレター構成など)を持つ。詳細は `references/kiji-nouhau.md` にまとまっているので、記事関連の依頼が来たら必ず読むこと。このSKILL.mdは要点への案内役であり、詳細ルールを勝手に省略・簡略化しない。

## 参照ファイル

- `references/kiji-nouhau.md`(このSkillフォルダ内) — X記事機能の基礎、マネタイズ8パターン、広告収益プログラムの条件、ジャンル選定、タイトルの作り方、セールスレター型の記事構成、信頼構築の技法、プロンプト設計の型、キュレーション型記事、販売・ローンチ運用、指標の見方、運用・リサーチの実務など全項目

## 最初に確認すること

1. **タイトルは必ずユーザーが決めたものを使う**。AIにタイトルを考えさせない(日本語のAI生成タイトルは不自然さが抜けにくいという運用上の理由)。タイトル未指定で依頼された場合は、まずユーザーにタイトルを決めてもらうよう伝える
2. どのマネタイズ手段(X広告収益/note等の自社コンテンツ販売/アフィリエイト等)を狙う記事かを確認する。狙う手段によってジャンル選定・記事末尾のCTA設計が変わる
3. `@Atsumori_FIRE` アカウント向けの記事の場合、`x-post` Skillが持つトーン・コンプライアンスルール(グレー表現には`[グレー: 理由]`を付ける、断定的な利益表現・元本保証の明言はしない等)と矛盾しないよう適用する

## 基本フロー(Claude Codeとの記事制作)

1. ユーザーが決めたタイトルを受け取る
2. `references/kiji-nouhau.md` の「記事作成の型(セールスレター型)」「タイトルの作り方」「信頼構築・説得力を高める技法」を踏まえて構成案(見出し・各セクションの狙い)を提示する
3. ユーザーが構成案を確認・修正指示
4. 構成が固まってから本文を執筆する。プロンプト公開型にする場合は `references/kiji-nouhau.md` の「プロンプト設計の型」に沿う
5. 参考記事の文章そのものをコピー・軽微な言い換えで使うことは禁止。需要(テーマ・ターゲット・悩み・切り口)だけを参考にし、文章と構成はゼロから作る

## 注意

- 記事内の実績数値・引用元の発言は、`references/kiji-nouhau.md`にある通り自己申告ベースで裏取りされていないものを含む。数字を扱う際は誇張・捏造をしない
- 第三者(専門家・インフルエンサー)の発言を引用する記事(キュレーション型)を作る場合は、出典明記と免責文言を必ず入れる(`references/kiji-nouhau.md`の該当セクション参照)

## 参考記事データベースへの追加

`references/kiji-nouhau.md`の「リサーチ・モデリング」に沿って、他アカウントの伸びている記事を蓄積するワークフロー。実体はGoogleスプレッドシート(シート名「記事データベース」)で、Firecrawl APIで本文を取得してから需要抽出して1行追記する。セットアップ手順は `README.md` の「10. (任意) X記事(キジ)の参考記事データベースを使う」を参照(未設定なら先にユーザーへセットアップを促す)。

1. `npm run scrape-article -- "<URL>"` を実行し、本文(markdown)とタイトルを取得する
   - Xはログインなしだとページが正しく取得できないことがある。失敗した場合や本文が空の場合は、ユーザーに記事の内容をコピー&ペーストしてもらうようフォールバックする
2. 取得した本文を読み、以下を分析する(`DEMAND_EXTRACTION_METHOD.md`と同様、需要=テーマ・ターゲット・悩み・切り口だけを抽出する視点で):
   - `genre`: 記事のジャンル(例: AI系、資産形成系など)
   - `demandMemo`: 「テーマ:.../ターゲット:.../悩み:.../切り口:...」の形式で簡潔にまとめる
   - `author` / `title` / `postedAt`: 本文・ページから読み取れる範囲で埋める(不明なら空文字でよい)
   - `impressions` / `bookmarks`: 本文中に表示回数・ブックマーク数が含まれていれば数値を入れる。読み取れない場合は空文字のままにし、憶測で数値を作らない
3. `npm run add-article -- '<JSON>'` で1行追記する。JSONの形式は `{"url":"...","author":"...","title":"...","postedAt":"...","impressions":"...","bookmarks":"...","genre":"...","demandMemo":"..."}`
4. 追記後、何を記録したか(タイトル・ジャンル・需要メモの要点)を一言でユーザーに報告する
