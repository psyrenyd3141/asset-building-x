# X記事(キジ)作成 — スクール講師グルコンのノウハウ + 本人提供ナレッジ

X記事は短文ポストとは全く別のノウハウ体系(引用戦略・マネタイズ・タイトル設計・セールスレター構成など)を持つ。このSkillには2系統の資料がある。

- **`production/𝕏記事作成ナレッジ.md`**(講師が直接提供した作成プロセス) — **実際に記事を1本作る作業の進め方はこれが優先・正**。目的設定→参考記事選定→タイトル決定(本人のみ)→構成(要確認)→本文→引用→公開前点検、という7工程と、AIへの禁止事項・ファイル保存規約が定義されている。記事を作る依頼が来たら、まずこのファイルの手順に従う
- `references/kiji-nouhau.md`(グルコン文字起こしからの抽出) — ジャンル選定・タイトルの心理学・市場の広さの考え方・販売ノウハウなど、進め方の「背景にある考え方・判断基準」を補う。`production/𝕏記事作成ナレッジ.md` の各工程を実行する際に、判断に迷ったらこちらを参照する。両者が重複・矛盾する場合は `production/𝕏記事作成ナレッジ.md` を優先する

## 参照ファイル

- `production/𝕏記事作成ナレッジ.md` — **記事作成プロセスの正本**。作成順・タイトルのパイ(市場の広さ)の数え方・参考記事の選び方(狙いごとの指標)・構成6ブロック・本文のルール・引用5本の作り方・公開前点検・AIへの禁止事項
- `production/自分の情報.md` — `@Atsumori_FIRE`のX記事運用における前提(マネタイズ方針、ジャンル優先順位、誘導先、トーン・コンプライアンスの参照先)。記事作成の最初に必ず読む
- `production/参考記事/` / `production/素材/` / `production/完成した記事/` — `𝕏記事作成ナレッジ.md`が要求するフォルダ。参考記事・一次情報素材・完成記事の保存場所(各フォルダのREADME.md参照)
- `references/kiji-nouhau.md`(このSkillフォルダ内) — X記事機能の基礎、マネタイズ8パターン、広告収益プログラムの条件、ジャンル選定、タイトルの作り方、タイトル心理学16原則、セールスレター型の記事構成、信頼構築の技法、プロンプト設計の型、キュレーション型記事、販売・ローンチ運用、指標の見方、運用・リサーチの実務など全項目

## 最初に確認すること

1. `production/自分の情報.md` を読み、マネタイズ方針・ジャンル優先順位・誘導先を把握する
2. **タイトルは必ずユーザーが決めたものを使う**。AIにタイトルを考えさせない、言い換え案も出さない(日本語のAI生成タイトルは不自然さが抜けにくいという運用上の理由)。タイトル未指定で依頼された場合は、まずユーザーにタイトルを決めてもらうよう伝える
3. どのマネタイズ手段(X広告収益/note等の自社コンテンツ販売/アフィリエイト等)を狙う記事かを確認する。狙う手段によって選ぶ参考記事の指標(`𝕏記事作成ナレッジ.md`の表参照)・ジャンル選定・記事末尾のCTA設計が変わる
4. `@Atsumori_FIRE` アカウント向けの記事の場合、`x-post` Skillが持つトーン・コンプライアンスルール(グレー表現には`[グレー: 理由]`を付ける、断定的な利益表現・元本保証の明言はしない等)と矛盾しないよう適用する

## 基本フロー(Claude Codeとの記事制作)

`production/𝕏記事作成ナレッジ.md` の7工程(目的→参考記事選定→タイトル→構成→本文→引用→公開前点検)に従う。各工程でのAIの振る舞いの要点:

1. 目的(読者・読後の理解・出口・狙う数字)を確定してから参考記事を選ぶ。参考記事は最低5本、`production/参考記事/` に保存する
2. 構成案を提示したら、**ユーザーがOKを出すまで本文を書き始めない**(`references/kiji-nouhau.md`の「記事作成の型(セールスレター型)」「信頼構築・説得力を高める技法」も構成案作りの参考にする)
3. AI系ジャンルの記事では、構成OK後・本文執筆前に「記事内にプロンプトをどこに入れるか」の配置提案を行う(`references/kiji-nouhau.md`の「プロンプト設計の型」参照。AI系以外のジャンルでは不要)
4. 本文執筆後、自己引用5本(入口を分ける)を作り、公開前点検を行う
5. 参考記事の文章そのものをコピー・軽微な言い換えで使うことは禁止。需要(テーマ・ターゲット・悩み・切り口)だけを参考にし、文章と構成はゼロから作る
6. 完成したら `production/完成した記事/YYYY-MM-DD_テーマ/` に `𝕏記事作成ナレッジ.md`が指定するファイル一式を保存する

## 注意

- 記事内の実績数値・引用元の発言は、`references/kiji-nouhau.md`にある通り自己申告ベースで裏取りされていないものを含む。数字を扱う際は誇張・捏造をしない
- 第三者(専門家・インフルエンサー)の発言を引用する記事(キュレーション型)を作る場合は、出典明記と免責文言を必ず入れる(`references/kiji-nouhau.md`の該当セクション参照)

## 参考記事データベースへの追加

`references/kiji-nouhau.md`の「リサーチ・モデリング」に沿って、他アカウントの伸びている記事を蓄積するワークフロー。実体はGoogleスプレッドシート(シート名「記事データベース」)で、Firecrawl APIで本文を取得してから需要抽出して1行追記する。セットアップ手順は `README.md` の「10. (任意) X記事(キジ)の参考記事データベースを使う」を参照(未設定なら先にユーザーへセットアップを促す)。

1. `npm run scrape-article -- "<URL>"` を実行し、本文(markdown)とタイトルを取得する
   - Xはログインなしだとページが正しく取得できないことがある。失敗した場合や本文が空の場合は、ユーザーに記事の内容をコピー&ペーストしてもらうようフォールバックする
2. 取得した本文を読み、以下を分析する(`DEMAND_EXTRACTION_METHOD.md`と同様、需要=テーマ・ターゲット・悩み・切り口だけを抽出する視点で):
   - `genre`: 記事のジャンル(例: AI系、資産形成系など)
   - `demandMemo`: 「テーマ:.../ターゲット:.../悩み:.../切り口:...」の形式で簡潔にまとめる
   - `author` / `title` / `postedAt`: 本文・ページから読み取れる範囲で埋める(不明なら空文字でよい)
   - `impressions` / `bookmarks`: 本文中に表示回数・ブックマーク数が含まれていれば数値を入れる。読み取れない場合は空文字のままにし、憶測で数値を作らない
3. `npm run add-article -- '<JSON>'` で1行追記する。JSONの形式は `{"url":"...","author":"...","title":"...","postedAt":"...","impressions":"...","bookmarks":"...","genre":"...","demandMemo":"..."}`
4. 追記後、何を記録したか(タイトル・ジャンル・需要メモの要点)を一言でユーザーに報告する
