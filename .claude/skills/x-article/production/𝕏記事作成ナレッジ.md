# 𝕏記事作成ナレッジ

このナレッジは、Claude CodeまたはCodexで使います。

**Claude CodeとCodexのどちらを選ぶかで、記事の質は決まりません。**
質を左右するのは、使うモデル、参考記事、元になる情報、タイトル、構成、確認工程です。

品質を優先するときの目安は次のとおりです。

- Claude Code: Opus 5
- Codex: Sol・xhigh

## 最初にすること

このファイルと同じフォルダに、次のものを入れてください。

1. `自分の情報.md`
2. `参考記事/` フォルダ
3. `素材/` フォルダ
4. `完成した記事/` フォルダ

最初の声かけはこれだけです。

```text
𝕏記事を作りたい。最初に必要なファイルを確認して、足りない情報だけ質問してください。
```

## AIが最初に確認するもの

AIは本文を書く前に、必ず次の順で確認します。

1. このナレッジ
2. `自分の情報.md`
3. `参考記事/` の全文
4. `素材/` の事実・数字・体験
5. `完成した記事/` の直近2本

ファイルが足りない場合は、勝手に補わず質問します。

## 作成の順番

### 1. 目的を決める

最初に次の4つを確定します。

- 誰に読んでほしいか
- 読後に何を理解してほしいか
- 記事の出口(note / 公式LINE / オープンチャット / X広告収益)
- この記事で狙うもの(表示回数 / ブックマーク / リストイン / 販売)

**出口と狙う数字が違えば、選ぶ参考記事も構成も変わります。**

### 2. 参考記事を選ぶ

参考記事は最低5本入れます。AIは表示回数だけで選びません。

| 狙い | 優先して見る数字 |
|---|---|
| X広告収益 | 表示回数・引用の強さ |
| 保存 | ブックマーク率・ブックマーク÷いいね |
| リストイン | CTAまでの整合性・誘導先の増加 |
| 販売 | 読了の流れ・商品の必要性へのつながり |

**ブックマーク率 = ブックマーク数 ÷ 表示回数**です。

- 0.05%未満: 表示は出ても、本文の保存力は弱い可能性がある
- 0.1〜0.2%: 保存されている
- 0.2%以上: 本文の構成を詳しく見る候補

動画つきの引用で表示が伸びた記事は、記事本文の実力と分けて扱います。

AIは5本を読んだあと、次を表で出します。

- タイトルの型
- 冒頭3行の役割
- 見出しの順番
- 保存したくなる具体物
- 信頼につながる事実
- CTAへのつなぎ方
- 借りる構造
- 借りてはいけない表現

### 3. タイトルは本人が決める

**AIはタイトル案を作りません。**タイトルは、記事を書く本人が自分で決めて持ってきます。
AIは日本語の細かい感覚が弱く、タイトルを任せると伸びるタイトルになりません。

本人がタイトルを持ってきたら、AIは次だけを確かめます。

- 参考にしたタイトル(伸びた記事)が `参考記事/` に入っているか
- 本文・プロフィール・出口とつながっているか

タイトルに次の条件が積まれるほど、対象者は減ります。AIは条件の数を数えて本人に伝えます。

- 読者の現状
- 持ち物や関心の前提
- 手段の固有名やカテゴリー名
- 「売る・書く・集める」など、手段を選んだ人だけに当てはまる動詞
- 「〜な人」「〜へ」などの読者の名指し
- 関係性の指定

条件数の目安:

- 0個: パイ7〜8
- 1個: パイ5〜6
- 2個: パイ4
- 3個以上: パイ3

**AIは言い換え案を出しません。**直すかどうか、どう直すかは本人が決めます。
**本人がタイトルを決めるまで構成へ進みません。**

### 4. 構成を作る

選んだタイトルで、本文の前に次を決めます。

- 読者の悩みと、その奥の本音
- 読者が信じている間違った常識
- 記事で渡す新しい見方
- 行動前に必要な認識の変化
- 記事タイプ
- 見出し
- 記事内で渡す具体物
- CTAへの橋
- 引用で使う入口

構成の基本は次の6ブロックです。

1. フック
2. 前提の転換
3. 番号つきの本文
4. そのまま使える具体物
5. まとめ
6. CTA

AIは構成案と設計理由を見せます。
**人がOKを出すまで本文へ進みません。**

### 5. 本文を書く

本文は5,000〜10,000字を目安にします。ただし、字数を埋めるために繰り返しません。

- 冒頭でタイトルの約束を回収する
- 何の話かを早い段階で明らかにする
- 各見出しに次を読む理由を置く
- 並列する情報は箇条書きにまとめる
- 事例だけで終わらせず、読者が使える手順・一覧・指示文を置く
- 数字は出どころを確認する
- 本人が体験していないことを体験談として書かない
- 他人の文章・固有の呼び名を使わない
- 根拠のない断言をしない
- 文章を整えすぎて説明文にしない

AIは素材に無い事実を補いません。不明点は `[要確認]` と書きます。

### 6. 引用を同時に作る

記事だけでは届かないため、公開前に引用も作ります。

- 自己引用5本
- 1本ずつ入口を変える
- 本文の要約だけにしない
- 数字・意外な一言・疑問・失敗・結果などから分ける
- 記事より対象者を狭めない

匿名の企画用アカウントでは、自己引用を1日3〜5回行います。

### 7. 公開前に点検する

AIは完成後、次を点検して結果を表にします。

- タイトルの約束を本文が回収しているか
- タイトルからCTAまで話がつながっているか
- 同じ内容を言い換えて繰り返していないか
- 参考記事の文章が残っていないか
- 事実・数字・体験を作っていないか
- 読者が持ち帰れる具体物があるか
- 各見出しが次を読む理由になっているか
- スマートフォンで読める改行か
- 引用5本の入口が重複していないか
- 直近2本と同じ言い回しを使い回していないか

問題があればAIが直し、もう一度点検します。

## 保存するもの

1記事につき、`完成した記事/YYYY-MM-DD_テーマ/` に次を保存します。

- `タイトル.md`(本人が決めたタイトルと、参考にしたタイトル)
- `参考記事の分析.md`
- `構成案.md`
- `article.md`
- `引用.md`
- `確認結果.md`

記事を公開したら、表示回数・ブックマーク数・ブックマーク率・リストイン数を追記します。
当たった理由と外した理由をこのナレッジへ足し、次の記事に使います。

## AIへの禁止事項

- タイトル案を作らない・言い換え案を出さない
- タイトルが決まる前に本文を書かない
- 構成のOK前に本文を書かない
- 足りない事実を想像で埋めない
- 参考記事の文章を言い換えただけの記事を作らない
- 表示回数だけで参考記事を評価しない
- 記事を作って引用を作らずに終わらない
- 一度の指示でタイトルから本文まで全部作らない

## 途中から再開するとき

```text
前回の続きから進めて。完成した記事フォルダにあるファイルを確認して、次に必要な工程だけやってください。
```
