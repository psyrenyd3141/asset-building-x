# Xポスト(短文)ドラフト作成 — @Atsumori_FIRE

このSkillは、Xアカウント「タヌコツ@サイドFIREの森」(@Atsumori_FIRE)向けの短文ポストを書く・書き直す・投稿案キューを補充する、あらゆる作業のエントリーポイントです。詳細なルールはリポジトリルートの3つのMarkdownファイルに分かれて既に整理されているので、このSkillの役目は「どの作業のときにどのファイルを読むべきか」を示すことです。ファイルの中身自体は運用しながら固められた正確な内容なので、このSKILL.mdから要約し直したり書き換えたりしない。必ず元ファイルを直接読むこと。

## 参照ファイル(いずれもリポジトリルート直下、このSkillフォルダの外)

| ファイル | いつ読むか |
|---|---|
| `ACCOUNT_GUIDELINES.md` | **どの作業でも必ず読む**。アカウントの立ち位置・トーン&マナー・コンプライアンスの扱い方・アフィリエイト表記・議論を呼ぶ投稿の分類・投稿スタイル・アルゴリズム対策・やらないこと・週間テーマ配分が書かれている |
| `DEMAND_EXTRACTION_METHOD.md` | 他アカウントの伸びている投稿を参考にする、または新しい切り口のオリジナル投稿をゼロから考えるとき。参考ポストを「需要」に分解する手順、新しい価値を加える6つの方法、投稿前チェックリストが書かれている |
| `POST_DRAFT_GUIDELINES.md` | `post_drafts_queue.yaml` を補充するとき。曜日別テーマ配分表、補充時の重複チェック・YAML検証の手順が書かれている |
| `references/growth-notes.md`(このSkillフォルダ内) | 構成タイプ(11種)の一覧・具体例、良い例悪い例の判断基準、相互リプライ施策など未確定事項の追加情報。新しい構成タイプで書きたいとき、判断に迷ったときに読む |

## 作業の判定とワークフロー

依頼の種類によって読むファイルを変える:

1. **単発の投稿ドラフト作成・リライト依頼**(例:「この話を投稿にして」「このポストをうちのアカウント向けにリライトして」)
   - `ACCOUNT_GUIDELINES.md` を読む
   - 参考にする元ネタがある場合は `DEMAND_EXTRACTION_METHOD.md` の手順で「需要(テーマ・ターゲット・悩み・切り口)」だけを抽出し、文章はゼロから書く(元の文章表現をコピー・軽微な言い換えで使うのは禁止)
   - 構成タイプ(誤解訂正型・逆説型・Before/After型など)は連発せず、直近の投稿と話題・型が被っていないか意識する

2. **`post_drafts_queue.yaml` の補充依頼**(例:「残りが少ないから次の30日分を追記して」)
   - `ACCOUNT_GUIDELINES.md` と `POST_DRAFT_GUIDELINES.md` の両方を読む
   - 曜日別テーマ配分表に沿ってテーマを割り当てる
   - 既存の `post_drafts_queue.yaml` と `git log` を確認し、直近使った切り口・フック・トピックと重複しないようにする
   - 追記後は `python3 -c "import yaml; yaml.safe_load(open('post_drafts_queue.yaml'))"` などでYAMLとして正しくパースできるか検証してからコミット・プッシュする

3. **他アカウントの投稿を参考にした分析依頼**(例:「このポストがなぜ伸びたか分析して」)
   - `DEMAND_EXTRACTION_METHOD.md` の「AIに分析を依頼するときの頼み方」に沿って、需要(テーマ・ターゲット・悩み・切り口)だけを抽出する。元の文章表現は参考にせず使わない

## 実行前に必ず確認する最重要ルール(3ファイルの要点)

- 丁寧語に限定しない。口語・自虐・スラングを混ぜ、整いすぎたAI感のある文章(「〜が重要です」等)を避ける
- 数字は実績ベースの具体的な値、またはシミュレーションなら前提条件を明記したものだけを使う。架空の実績数値は作らない
- 文末は「独り言」または「賛否どちらの立場からもリプが生まれる挑発的な質問」で締める。「〜ですよね?」のような義務的な相槌しか許さない質問は使わない
- グレーな表現(元本保証や断定的な利益表現に近いもの)は使ってよいが、投稿文の末尾に `[グレー: 理由]` を付けて最終判断をユーザーに委ねる。元本保証を明言する等の明確にアウトな表現だけは使わない
- アフィリエイト表記(PBR LENDINGの"最大"年率12%など)は公式の正確な表現を確認してから使う

これらは要約であり、実際の作業では必ず元ファイルを読んで詳細ルールに従うこと。
